## 5. 과목별 압축 이론

### 5.1 DB

핵심 주제: 스키마 3단계, 데이터 모델, 관계 데이터 모델, 관계대수/관계해석, 키, 정규화, 무결성, 트랜잭션, 회복, RAID, 파일 구조

마지막 암기:

- 키: 슈퍼키는 유일성, 후보키는 유일성+최소성, 기본키는 후보키 중 대표, 대체키는 선택되지 않은 후보키, 외래키는 다른 릴레이션의 기본키 참조.
- 정규화: 1NF는 원자값, 2NF는 부분 함수 종속 제거, 3NF는 이행 함수 종속 제거, BCNF는 모든 결정자가 후보키.
- 트랜잭션 ACID: 원자성, 일관성, 격리성, 지속성.
- 회복: 로그 기반 회복에서 Undo는 미완료 작업 취소, Redo는 완료 작업 재반영.
- 무결성: 개체 무결성은 기본키 NULL 불가, 참조 무결성은 외래키가 참조 가능한 값이어야 함.

수업 문제 포인트:

- “현재 정규형이 어디까지인가”는 후보키와 함수 종속을 먼저 찾는다.
- 관계대수는 선택, 프로젝트, 조인, 합집합, 차집합 기호 의미를 묻는 문제가 많다.
- 트랜잭션은 ACID 영문 약어와 설명 매칭으로 자주 낸다.

### 5.2 네트워크/OS

핵심 주제: OSI 7계층, 계층별 PDU, 네트워크/응용/데이터링크 프로토콜, IP 주소, 서브넷, 라우팅, 페이지 교체, 스케줄링, UNIX 명령어, chmod

마지막 암기:

- OSI 7계층: 물리, 데이터링크, 네트워크, 전송, 세션, 표현, 응용.
- TCP는 연결형, 신뢰성, 순서 보장. UDP는 비연결형, 빠름, 오버헤드 적음.
- ARP는 IP 주소를 MAC 주소로 변환, RARP는 MAC 주소를 IP 주소로 변환.
- 페이지 교체: FIFO는 먼저 들어온 페이지 제거, LRU는 가장 오래 사용되지 않은 페이지 제거, OPT는 앞으로 가장 늦게 쓰일 페이지 제거.
- chmod 754: 소유자 rwx, 그룹 r-x, 기타 r--.

수업 문제 포인트:

- 서브넷 문제는 프리픽스 길이에서 호스트 비트 수를 구한 뒤 2^n - 2를 계산한다.
- 스케줄링 문제는 도착시간, 실행시간, 선점 여부를 표로 그린다.
- chmod는 4 읽기, 2 쓰기, 1 실행을 합산한다.

### 5.3 SW개발

핵심 주제: 테스트 레벨, 테스트 커버리지, 블랙박스 테스트, 테스트 자동화, 테스트 케이스, 인터페이스 보안, 데이터 표현 형식, 웹서비스, EAI/ESB, 형상관리

마지막 암기:

- 테스트 레벨: 단위, 통합, 시스템, 인수.
- 블랙박스 테스트: 동등 분할, 경계값 분석, 원인-결과 그래프, 오류 예측, 결정 테이블, 상태 전이.
- 테스트 커버리지: 구문/문장, 결정/분기, 조건, 조건/결정, 변경 조건/결정(MC/DC), 다중 조건.
- 테스트 자동화 구성요소: 드라이버, 스텁, 슈트, 스크립트, 목 오브젝트 등.
- 형상관리 활동: 식별, 통제, 감사, 기록.

수업 문제 포인트:

- “입력값 범위의 경계”가 보이면 경계값 분석.
- “동등한 성격의 입력 묶음”이 보이면 동등 분할.
- “상태가 바뀌며 결과가 달라짐”이 보이면 상태 전이 테스트.

### 5.4 SW설계

핵심 주제: 디자인 패턴, 응집도/결합도, UML, 클래스 다이어그램 관계, 4+1 뷰, SOLID, 럼바우, UI, 애자일, 리팩토링, 비용 산정

마지막 암기:

- 생성 패턴: Singleton, Factory Method, Abstract Factory, Builder, Prototype.
- 구조 패턴: Adapter, Bridge, Composite, Decorator, Facade, Flyweight, Proxy.
- 행위 패턴: Strategy, Observer, Command, Iterator, State, Visitor, Mediator, Memento, Template Method, Chain of Responsibility, Interpreter.
- 응집도는 기능적 응집도가 가장 좋고, 우연적 응집도가 가장 나쁘다.
- 결합도는 자료 결합이 낮고 좋은 편이며, 내용 결합이 높고 나쁜 편이다.
- UML 일반화는 빈 삼각형, 집합은 빈 마름모, 합성은 채운 마름모, 의존은 점선 화살표.

수업 문제 포인트:

- 디자인 패턴은 이름보다 “상황”을 먼저 본다.
- 응집도/결합도는 “좋은 설계일수록 응집도는 높고 결합도는 낮다”가 기준이다.
- SOLID는 단일 책임, 개방 폐쇄, 리스코프 치환, 인터페이스 분리, 의존 역전.

### 5.5 보안/신기술

핵심 주제: 암호 알고리즘, 공격 유형, 웹 공격, DoS/DDoS/DRDoS, 사회공학, 취약점 생명주기, 악성코드, 정보보호, 접근통제, 인증기술, 보안 솔루션, 신기술

마지막 암기:

- CIA: 기밀성, 무결성, 가용성.
- 3A: Authentication, Authorization, Accounting.
- SQL Injection은 입력값에 SQL 구문을 삽입해 DB를 조작하는 공격.
- XSS는 악성 스크립트를 삽입해 사용자의 브라우저에서 실행시키는 공격.
- CSRF는 인증된 사용자의 권한을 이용해 원치 않는 요청을 보내게 하는 공격.
- 접근통제: DAC는 소유자 중심, MAC은 보안 등급 중심, RBAC는 역할 중심.
- 보안 솔루션: IDS는 탐지, IPS는 차단, WAF는 웹 방화벽, DLP는 정보 유출 방지, SIEM은 로그 통합 분석.

수업 문제 포인트:

- 공격 유형 문제는 “공격자가 무엇을 속였는지, 무엇을 고갈시켰는지, 어디에 삽입했는지”를 본다.
- 보안 솔루션은 약어의 역할을 한 줄로 적는 연습이 가장 효율적이다.
- 신기술은 정의형 단답으로 묻는 경우가 많아 키워드 중심으로 정리한다.

### 5.6 C언어

핵심 주제: 포인터, 이중 포인터, 포인터 산술, 배열, 문자열, 구조체, 구조체 포인터, 연결 리스트, 스택/큐, 재귀, 비트/논리/삼항 연산자

풀이 순서:

1. 변수와 배열의 초기값을 표로 쓴다.
2. 포인터가 가리키는 대상을 화살표로 표시한다.
3. 증감 연산자가 전위인지 후위인지 확인한다.
4. 반복문마다 변경된 값을 한 줄씩 기록한다.
5. printf의 출력 형식과 줄바꿈을 마지막에 확인한다.

주의:

- `p + 1`은 주소값 1 증가가 아니라 자료형 크기만큼 다음 원소로 이동한다.
- 문자열은 마지막에 널 문자 `\0`이 있다는 전제를 둔다.
- 구조체 포인터는 `p->x`가 `(*p).x`와 같다.

### 5.7 Java

핵심 주제: 클래스/객체, 생성자, 상속, 오버라이딩, 오버로딩, 필드 하이딩, static, 인터페이스, 추상 클래스, 예외, 제네릭, 람다, String 비교

풀이 순서:

1. 실제 객체 타입과 참조 변수 타입을 구분한다.
2. 필드는 참조 변수 타입 기준, 오버라이딩 메서드는 실제 객체 타입 기준으로 본다.
3. 생성자 호출 순서는 부모 생성자 후 자식 생성자다.
4. static 멤버는 객체별 값이 아니라 클래스 공유 값이다.
5. 문자열 비교는 `==`와 `equals()`를 구분한다.

주의:

- 오버라이딩은 동적 바인딩, 오버로딩은 컴파일 시점 매개변수로 선택된다.
- `super()`와 `this()`는 생성자 첫 줄에서만 호출 가능하다.

### 5.8 Python

핵심 주제: 리스트, 문자열, 슬라이싱, 함수, 기본 제공 함수, 딕셔너리, 집합, 제너레이터 표현식, 클래스, 재귀

풀이 순서:

1. 슬라이싱은 `start:stop:step` 순서로 해석하고, stop은 포함하지 않는다.
2. 리스트와 문자열 인덱스를 0부터 적는다.
3. 딕셔너리는 키 존재 여부와 `get(key, default)` 결과를 확인한다.
4. 반복문에서 누적되는 값은 표로 추적한다.
5. 출력은 리스트 형태인지 문자열 형태인지 그대로 쓴다.

주의:

- `a[::-1]`은 역순이다.
- `range(1, 5)`는 1, 2, 3, 4다.
- `set`은 중복을 제거하며 순서를 보장하지 않는 것으로 본다.

### 5.9 SQL

핵심 주제: SELECT, WHERE, GROUP BY, HAVING, ORDER BY, 집계함수, JOIN, 서브쿼리, DML, DDL, DCL

풀이 순서:

1. FROM/JOIN으로 대상 행을 만든다.
2. WHERE로 행을 필터링한다.
3. GROUP BY로 묶는다.
4. HAVING으로 그룹을 필터링한다.
5. SELECT로 출력 컬럼을 만든다.
6. ORDER BY로 정렬한다.

주의:

- `COUNT(*)`는 NULL 포함 행 수, `COUNT(컬럼)`은 해당 컬럼의 NULL을 제외한 개수다.
- WHERE는 그룹화 전 조건, HAVING은 그룹화 후 조건이다.
- INNER JOIN은 매칭되는 행만, LEFT JOIN은 왼쪽 테이블을 모두 남긴다.

## 7. 실전 풀이 루틴

### 이론형

1. 문제의 단서어에 밑줄을 긋는다.
2. “정의형, 구분형, 사례형, 계산형” 중 어떤 문제인지 분류한다.
3. 용어가 기억나지 않으면 한글 뜻, 역할, 반대 개념을 먼저 쓴다.
4. 답안은 길게 쓰기보다 채점 키워드를 앞쪽에 둔다.

### 코딩형

1. 출력문부터 찾는다.
2. 출력에 필요한 변수만 추적한다.
3. 반복문은 회차별 표로 적는다.
4. 전위/후위 증감, 정수 나눗셈, 슬라이싱 범위, 동적 바인딩을 확인한다.
5. 마지막에 공백, 쉼표, 대괄호 등 출력 형식을 맞춘다.

1. 테이블을 먼저 작게 다시 그린다.
2. WHERE와 HAVING을 혼동하지 않는다.
3. JOIN 결과 행 수를 먼저 센다.
4. NULL 처리와 COUNT 기준을 확인한다.
5. ORDER BY가 있으면 최종 정렬 후 답을 쓴다.
