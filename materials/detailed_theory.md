# 정보처리기사 실기 상세 이론

학습 순서: 개념의 정의를 읽고, 비교 기준을 확인한 다음 예제를 직접 계산한다. 각 분야의 연습문제와 연결해 틀린 이유를 한 문장으로 정리한다.

## DB

### 1. 데이터베이스 설계와 스키마

요구사항 분석은 필요한 데이터와 처리 규칙을 확인하는 단계다. 개념적 설계에서는 개체, 속성, 관계를 ER 모델로 표현한다. 논리적 설계에서는 이를 관계형 테이블과 키로 변환하고 정규화한다. 물리적 설계에서는 실제 저장 구조, 인덱스, 파티션 등을 선택한다.

| 구분 | 보는 관점 | 예시 |
|---|---|---|
| 외부 스키마 | 특정 사용자나 프로그램에 필요한 데이터 | 학생에게는 본인의 성적만 보이는 뷰 |
| 개념 스키마 | 데이터베이스 전체의 논리적 구조 | 학생·수강·과목 테이블과 제약조건 |
| 내부 스키마 | 저장 장치에서의 물리적 표현 | 페이지, 파일 구성, 인덱스 |

논리적 데이터 독립성은 개념 스키마 변경이 외부 스키마에 미치는 영향을 줄이는 성질이다. 물리적 데이터 독립성은 내부 저장 방식의 변경이 개념 스키마에 영향을 주지 않게 하는 성질이다. 설계 단계의 개념적·논리적·물리적 모델과 사용자 관점의 외부·개념·내부 스키마를 혼동하지 않는다.

### 2. 관계 모델, 키, 무결성

릴레이션은 테이블, 튜플은 행, 속성은 열, 도메인은 속성에 허용되는 값의 집합이다. 차수는 속성 수이고 카디널리티는 튜플 수다. 관계 모델에서 튜플과 속성의 나열 순서는 본질적인 의미가 없다.

| 키 | 판단 기준 | 예시 |
|---|---|---|
| 슈퍼키 | 행을 유일하게 구별 | 학번, 또는 학번과 이름을 함께 사용 |
| 후보키 | 유일성과 최소성을 동시에 만족 | 학번만으로 충분하면 학번이 후보키 |
| 기본키 | 후보키 중 대표로 선택 | STUDENT의 학번 |
| 대체키 | 기본키로 선택되지 않은 후보키 | 별도로 유일한 이메일 |
| 외래키 | 참조 대상의 키와 관계를 연결 | 수강 테이블의 학번 |

개체 무결성은 기본키의 유일성과 NULL 불가를 보장한다. 참조 무결성은 외래키 값이 참조 대상에 존재하거나, NULL을 허용하는 경우 NULL이어야 한다는 규칙이다. 도메인 무결성은 자료형, 범위, 형식 등의 제한을 지키는 것이다. SQL에서 외래키는 DBMS가 허용하는 기본키 또는 UNIQUE 키를 참조한다.

**후보키 계산 예제**: `수강(학번, 과목코드, 과목명, 성적)`에서 `과목코드 → 과목명`, `(학번, 과목코드) → 성적`이면 학번과 과목코드의 폐포가 전체 속성을 포함한다. 둘 중 하나를 제거하면 전체를 결정하지 못하므로 `(학번, 과목코드)`가 후보키다.

### 3. 이상 현상과 정규화

삽입 이상은 아직 수강생이 없는 과목 정보를 넣기 어려운 현상, 갱신 이상은 중복 저장된 교수명을 일부 행에서만 수정하는 현상, 삭제 이상은 마지막 수강생의 행을 삭제하면서 과목 정보까지 사라지는 현상이다.

| 정규형 | 점검할 조건 | 제거하는 문제 |
|---|---|---|
| 1NF | 각 속성 값이 원자값 | 한 칸에 여러 값을 함께 저장 |
| 2NF | 1NF이고 비주요 속성이 후보키 전체에 완전 종속 | 복합 후보키 일부에 대한 부분 종속 |
| 3NF | 2NF이고 비주요 속성의 이행 종속 제거 | 키 → 비키 속성 → 다른 비키 속성 |
| BCNF | 모든 비자명한 함수 종속의 결정자가 슈퍼키 | 후보키가 아닌 결정자로 생기는 문제 |
| 4NF | BCNF에 다치 종속 조건을 추가 | 서로 독립인 다중 값 조합의 중복 |
| 5NF | 불필요한 조인 종속 제거 | 더 작은 릴레이션으로 분해할 수 있는 조합 중복 |

실기 요약에서 BCNF를 “모든 결정자가 후보키”라고 표현하기도 한다. 엄밀한 조건은 결정자가 슈퍼키라는 것이다. 분해할 때는 원래 관계가 조인으로 복원되는 **무손실 분해**인지, 함수 종속을 분해된 테이블에서 검사할 수 있는 **종속성 보존**인지 확인한다.

**분해 예제**: `수강(학번, 과목코드, 과목명, 교수명, 성적)`을 `수강(학번, 과목코드, 성적)`과 `과목(과목코드, 과목명, 교수명)`으로 나누면 과목 정보의 부분 종속을 제거한다. 반정규화는 읽기 성능 등을 위해 일부 중복을 의도적으로 허용하는 작업이며, 갱신 불일치 관리가 필요하다.

### 4. 관계대수와 관계해석

| 연산 | 의미 | SQL과의 연결 |
|---|---|---|
| 선택 σ | 조건을 만족하는 행 | WHERE |
| 프로젝트 π | 지정한 속성만 남김 | SELECT DISTINCT 컬럼 |
| 조인 ⋈ | 조건에 따라 두 관계를 연결 | JOIN |
| 카티션 곱 × | 모든 행의 조합 | CROSS JOIN |
| 합집합 ∪ | 두 관계의 튜플을 합침 | UNION |
| 차집합 − | 첫 관계에만 있는 튜플 | EXCEPT 또는 MINUS |
| 디비전 ÷ | 상대 관계의 모든 값과 관련되는 값 | 모든 필수 과목을 수강한 학생 찾기 |

합집합·교집합·차집합은 속성 수와 대응 도메인이 호환되어야 한다. 관계대수는 결과를 얻는 절차를 연산으로 나타내고, 관계해석은 원하는 결과가 만족해야 할 조건을 표현한다.

### 5. 트랜잭션과 동시성

ACID의 원자성은 전부 수행하거나 전부 취소하는 성질, 일관성은 제약조건을 유지하는 성질, 격리성은 동시 실행의 간섭을 제어하는 성질, 지속성은 커밋한 결과를 장애 후에도 보존하는 성질이다.

| 이상 현상 | 상황 |
|---|---|
| Dirty Read | 다른 트랜잭션이 커밋하지 않은 값을 읽음 |
| Non-repeatable Read | 같은 행을 다시 읽었는데 값이 달라짐 |
| Phantom Read | 같은 조건을 다시 조회했는데 대상 행 집합이 달라짐 |
| Lost Update | 동시에 수정하다 한쪽 변경을 덮어씀 |

일반적인 격리 수준은 Read Uncommitted, Read Committed, Repeatable Read, Serializable 순서로 강해진다. 실제 차단 방식과 Phantom 방지 여부는 DBMS 구현을 함께 확인한다. 공유 잠금은 읽기, 배타 잠금은 수정에 쓰이며, 2단계 잠금은 잠금을 얻는 확장 단계와 해제하는 축소 단계를 분리한다. 교착상태는 대기 그래프, 시간 제한, 예방·회피·탐지 후 회복 등으로 다룬다.

### 6. 회복, 인덱스, 저장 구조

WAL은 데이터 페이지보다 복구에 필요한 로그를 먼저 안정적인 저장소에 기록하는 규칙이다. Undo는 완료되지 않은 변경을 되돌리고, Redo는 필요한 완료 변경을 다시 적용한다. 체크포인트는 복구 시 검사해야 할 범위를 줄이는 기준점이다.

B+ 트리는 정렬된 키와 범위 검색에 적합하다. 해시 인덱스는 동등 비교에 유리하지만 일반적으로 범위 조회에는 적합하지 않다. 인덱스는 읽기를 빠르게 할 수 있지만 INSERT·UPDATE·DELETE의 유지 비용과 저장 공간이 필요하다.

| RAID | 핵심 구성 | 특징 |
|---|---|---|
| 0 | 스트라이핑 | 분산 기록, 자체 중복 보호 없음 |
| 1 | 미러링 | 같은 데이터를 복제 |
| 5 | 분산 패리티 | 최소 3개 디스크, 1개 장애 허용 |
| 6 | 이중 분산 패리티 | 최소 4개 디스크, 2개 장애 허용 |

**실수 점검**: 후보키는 최소성을 확인한다. 외래키와 기본키의 역할을 바꾸어 쓰지 않는다. 2NF와 3NF는 각각 부분 종속과 이행 종속을 구분한다.

## 네트워크/OS

### 1. OSI 계층과 전송 단위

| 계층 | 역할 | 대표 예시·전송 단위 |
|---|---|---|
| 7 응용 | 사용자 프로그램의 네트워크 서비스 | HTTP, FTP, SMTP, DNS |
| 6 표현 | 형식 변환·압축·암호화 | 데이터 표현 방식 |
| 5 세션 | 대화의 설정·유지·동기화 | 세션 관리 |
| 4 전송 | 프로세스 간 통신과 포트 | TCP 세그먼트, UDP 데이터그램 |
| 3 네트워크 | 논리 주소와 경로 선택 | IP 패킷, 라우터 |
| 2 데이터링크 | 같은 링크 내 전달·프레임 | Ethernet 프레임, 스위치 |
| 1 물리 | 신호 전송 | 비트, 케이블 |

TCP/IP 모델과 OSI 모델은 계층을 묶는 방식이 다르다. ARP는 같은 링크에서 IPv4 주소에 대응하는 MAC 주소를 알아내는 데 사용하고, ICMP는 오류 보고와 진단에 사용한다. `ping`과 `traceroute`의 목적을 구별한다.

### 2. TCP, UDP, 응용 프로토콜

TCP는 연결을 설정하고 순서·재전송·흐름 제어 등을 제공한다. UDP는 연결 설정 없이 데이터그램을 전송하며 전달·순서·중복 방지를 보장하지 않는다. UDP를 쓰는 응용도 필요한 신뢰성을 별도로 구현할 수 있다.

| 프로토콜 | 주된 목적 | 대표 포트 |
|---|---|---|
| HTTP / HTTPS | 웹 | 80 / 443 |
| FTP | 파일 전송 | 제어 21, 능동 모드 데이터 20 |
| SSH | 암호화된 원격 접속 | 22 |
| SMTP | 메일 전송 | 25 |
| DNS | 이름과 주소 조회 | 53, UDP와 TCP 사용 |
| DHCP | IP 설정 자동 할당 | 서버 67, 클라이언트 68 |
| SNMP | 네트워크 관리 | 161, 알림 162 |

TCP 연결 설정은 SYN, SYN/ACK, ACK의 3-way handshake다. 회선 교환은 통신 전에 전용 경로를 확보하고, 패킷 교환은 데이터를 나눠 공유 네트워크로 보낸다. CRC는 오류 검출에 사용하며, 오류 정정 코드와 동일하게 취급하지 않는다.

### 3. IPv4와 서브넷 계산

IPv4는 32비트다. `/n`은 네트워크 프리픽스가 n비트라는 뜻이다. 일반적인 다중 접근 서브넷에서 호스트 비트 h가 2 이상일 때 사용 가능 호스트 수는 `2^h - 2`다. 네트워크 주소와 브로드캐스트 주소를 제외하기 때문이다. `/31` 점대점 링크와 `/32` 단일 호스트에는 이 식을 그대로 적용하지 않는다.

**예제: `192.168.10.130/26`**

1. 호스트 비트: `32 - 26 = 6`.
2. 마스크: `255.255.255.192`.
3. 마지막 옥텟 블록 크기: `256 - 192 = 64`.
4. 130이 속한 블록: 128–191.
5. 네트워크 주소: `192.168.10.128`, 브로드캐스트: `192.168.10.191`.
6. 사용 가능한 주소: 129–190, 총 62개.

라우팅 테이블에서는 목적지 주소와 일치하는 경로 중 가장 긴 프리픽스를 우선하는 Longest Prefix Match를 사용한다.

### 4. 라우팅 프로토콜

| 구분 | 알고리즘·용도 | 주의점 |
|---|---|---|
| RIP | Distance Vector, 홉 수 | 최대 유효 홉 15, 16은 도달 불가 |
| OSPF | Link State, 비용 기반 | 최단 경로 계산, 영역 구성 |
| BGP | Path Vector, AS 간 경로 교환 | 정책과 경로 속성이 중요 |

IGP는 하나의 AS 내부, EGP는 AS 사이의 경로 교환을 위한 분류다. BGP를 단순히 “홉 수가 가장 짧은 길”로만 설명하지 않는다.

### 5. 메모리와 페이지 교체

페이징은 고정 크기 페이지·프레임, 세그멘테이션은 논리적으로 의미 있는 가변 크기 구역을 사용한다. 내부 단편화는 할당한 공간 내부의 낭비, 외부 단편화는 가용 공간이 작은 조각으로 흩어진 문제다. 페이지 부재가 과도하여 실제 처리보다 교체에 시간을 쓰는 현상은 스래싱이다.

| 알고리즘 | 교체 기준 |
|---|---|
| FIFO | 메모리에 가장 먼저 들어온 페이지 |
| LRU | 과거에 가장 오래 사용하지 않은 페이지 |
| OPT | 앞으로 가장 늦게 사용할 페이지 |

**FIFO 예제**: 프레임 3개, 참조열 `1, 2, 3, 2, 4, 1, 2, 5`이면 부재 7회다. 중간의 2는 적중이다. FIFO에서는 적중해도 입장 순서가 바뀌지 않는다. LRU는 적중 시 최근 사용 시점이 바뀐다.

### 6. 프로세스 스케줄링

반환 시간은 완료 시간 − 도착 시간, 대기 시간은 반환 시간 − 실행 시간, 응답 시간은 첫 실행 시작 시간 − 도착 시간이다. 문맥 교환 비용이 주어졌다면 시간축에 반영한다.

| 방식 | 선택 기준 | 선점 |
|---|---|---|
| FCFS | 도착 순서 | 일반적으로 비선점 |
| SJF | 준비된 작업 중 실행 시간이 가장 짧음 | 비선점 |
| SRT | 남은 실행 시간이 가장 짧음 | 선점 |
| HRN | `(대기시간 + 실행시간) / 실행시간`이 가장 큼 | 비선점 |
| RR | 시간 할당량마다 순환 | 선점 |

**비선점 SJF 예제**: P1(도착 0, 실행 7), P2(2,4), P3(4,1)이면 P1 0–7, P3 7–8, P2 8–12다. 대기 시간은 각각 0, 6, 3이고 평균은 3이다. 실행 도중 더 짧은 작업이 도착해도 P1을 중단하지 않는다.

### 7. 동기화와 교착상태

임계구역은 공유 자원을 다루는 코드 영역이다. Mutex는 상호 배제를 위한 잠금, Semaphore는 카운터를 사용하는 동기화 수단이다. 교착상태의 네 필요 조건은 상호 배제, 점유와 대기, 비선점, 순환 대기다. Aging은 대기한 작업의 우선순위를 높여 기아를 완화하는 방식이다.

### 8. UNIX 명령어와 권한

`pwd`는 현재 경로, `ls`는 목록, `grep`은 텍스트 검색, `ps`는 프로세스 확인, `kill`은 시그널 전달, `chmod`는 권한 변경이다. 파이프 `|`는 앞 명령의 표준출력을 다음 명령의 표준입력으로 연결한다. `>`는 덮어쓰기, `>>`는 이어쓰기를 위한 출력 리다이렉션이다.

권한 비트는 읽기 4, 쓰기 2, 실행 1이다. `754`는 소유자 `rwx`, 그룹 `r-x`, 기타 `r--`다. 디렉터리의 실행 권한은 경로를 탐색하는 권한으로 이해한다.

**실수 점검**: SJF와 SRT의 선점 여부, FIFO와 LRU의 적중 처리, 프리픽스와 호스트 비트 수를 구별한다.

## SW개발

### 1. 검증, 확인, 테스트 레벨

Verification은 명세와 설계에 맞게 구현했는지 검증하고, Validation은 사용자가 필요로 하는 시스템인지 확인하는 관점이다. 리뷰·정적 분석은 실행하지 않고 살피는 정적 테스트이며, 실제 코드를 실행하는 것은 동적 테스트다.

| 레벨 | 범위 | 예시 |
|---|---|---|
| 단위 | 함수·클래스·모듈 | 할인 계산 함수의 반환값 |
| 통합 | 모듈 사이의 연결 | 주문 서비스와 결제 모듈의 호출 |
| 시스템 | 전체 시스템 | 기능, 성능, 보안 요구사항 |
| 인수 | 사용자·발주자의 수용 기준 | 실제 업무 시나리오와 계약 조건 |

하향식 통합에서는 아직 없는 하위 모듈을 Stub으로 대신한다. 상향식 통합에서는 하위 모듈을 호출할 상위 역할을 Driver로 대신한다. 회귀 테스트는 수정한 코드가 기존 기능을 깨뜨리지 않았는지 확인한다.

### 2. 블랙박스 기법

| 기법 | 기준 | 사례 |
|---|---|---|
| 동등 분할 | 같은 처리가 예상되는 입력 집합 | 유효 나이 범위와 범위 밖을 나누기 |
| 경계값 분석 | 범위 경계와 주변 | 1–100 입력에 0,1,2,99,100,101 |
| 결정 테이블 | 조건 조합과 동작 | 회원 여부·구매액에 따른 할인 |
| 상태 전이 | 현재 상태와 이벤트 | 로그인 실패 횟수에 따른 계정 잠금 |
| 원인-결과 그래프 | 입력 조건과 출력 관계 | 여러 입력 조건의 논리 조합 |
| 오류 추정 | 경험으로 오류를 예측 | 빈 문자열, 중복 요청, 잘못된 날짜 |

블랙박스는 외부 명세와 입출력 관점으로 시험한다. 화이트박스는 코드 구조와 내부 경로를 기준으로 시험한다. 오류 추정은 정해진 분할 공식이 아니라 경험 기반이다.

### 3. 커버리지와 MC/DC

문장 커버리지는 실행 가능한 문장, 분기 커버리지는 판단 결과의 참·거짓, 조건 커버리지는 개별 조건의 참·거짓을 점검한다. 조건/결정 커버리지는 두 기준을 함께 만족한다. MC/DC는 각 조건이 다른 조건과 독립적으로 전체 결정 결과를 바꾸는지 확인한다. 다중 조건 커버리지는 조건 값의 가능한 조합을 살핀다.

**예제: `A && B`**

| A | B | 결과 | 역할 |
|---|---|---|---|
| T | T | T | 기준 사례 |
| F | T | F | A의 독립 영향 비교 |
| T | F | F | B의 독립 영향 비교 |

위 세 사례는 다른 조건 값을 유지하면서 A와 B가 각각 결정을 바꾸는 것을 보여준다. 실제 코드의 단축 평가와 실행 가능한 조건 조합을 함께 확인한다. 분기 커버리지 100%가 모든 경로나 모든 조건 조합의 실행을 뜻하지는 않는다.

### 4. 테스트 케이스와 자동화

테스트 케이스에는 식별자, 테스트 목적, 사전 조건, 입력, 수행 절차, 예상 결과, 실제 결과 등이 들어간다. “정상 동작한다”보다 “금액 10000 입력 시 할인 후 9000을 반환한다”처럼 관찰 가능한 예상 결과가 좋다.

Test Suite는 테스트 묶음, Test Script는 수행 절차, Test Harness는 실행과 관찰을 지원하는 환경이다. Mock은 기대하는 상호작용을 검증하는 대역으로 사용할 수 있다. Stub·Driver·Mock의 역할을 구분한다.

### 5. 인터페이스와 데이터 형식

JSON은 객체·배열·기본 값으로 데이터를 표현하고, XML은 태그와 속성으로 구조를 표현한다. YAML은 들여쓰기 등을 사용하는 구성·데이터 표현 형식이다. JSON에는 표준적으로 주석 문법이 없고, YAML의 들여쓰기는 구조에 영향을 준다.

REST는 자원을 URI로 식별하고 HTTP 메서드 등을 사용하는 설계 스타일이다. SOAP는 XML 기반 메시지 규약이며 WSDL로 인터페이스를 기술하는 경우가 많다. 둘을 단순히 파일 형식으로 분류하지 않는다.

| 통신 방식 | 특징 |
|---|---|
| Fetch / AJAX | 브라우저에서 비동기 HTTP 요청 |
| WebSocket | 연결을 유지하며 양방향 통신 |
| GraphQL | 클라이언트가 필요한 필드를 질의 |
| EAI | 기업 애플리케이션 통합의 접근 방식 |
| ESB | 버스 구조로 메시지 전달·변환·연계를 지원 |

### 6. 인터페이스 보안과 형상관리

TLS는 전송 구간을 보호한다. IPSec의 AH는 인증·무결성에 초점을 맞추고, ESP는 기밀성을 포함한 보호를 제공할 수 있다. 전송 모드와 터널 모드는 보호하는 범위가 다르다. 입력 검증, 권한 확인, 오류 메시지 관리도 인터페이스 보호에 필요하다.

형상관리는 형상 식별, 형상 통제, 형상 상태 기록, 형상 감사로 정리한다. Baseline은 변경을 통제하는 기준 상태다. 단순 파일 백업과 변경 승인·이력·감사까지 포함하는 형상관리의 범위를 구별한다.

**실수 점검**: Stub은 하위, Driver는 상위 역할이다. 경계값과 동등 분할을 구분한다. 커버리지 이름은 무엇을 측정하는지와 함께 외운다.

## SW설계

### 1. 응집도와 결합도

응집도는 한 모듈 내부 요소가 같은 목적에 얼마나 관련되는지, 결합도는 모듈 사이의 의존이 얼마나 강한지 나타낸다. 좋은 설계는 높은 응집도와 낮은 결합도를 지향한다.

응집도는 일반적으로 **우연적 → 논리적 → 시간적 → 절차적 → 통신적 → 순차적 → 기능적** 순으로 강해진다. 통신적 응집은 같은 데이터, 순차적 응집은 앞 단계의 출력이 다음 단계의 입력, 기능적 응집은 하나의 기능이 기준이다.

결합도는 일반적으로 **내용 → 공통 → 외부 → 제어 → 스탬프 → 자료** 순으로 낮아진다. 공통 결합은 전역 데이터 공유, 제어 결합은 상대 모듈의 실행을 지시하는 제어 정보 전달, 스탬프 결합은 큰 자료 구조 전달, 자료 결합은 필요한 데이터 전달을 중심으로 이해한다.

### 2. SOLID

| 원칙 | 판단 기준 | 예시 |
|---|---|---|
| SRP 단일 책임 | 변경 이유를 한 책임에 집중 | 계산과 파일 출력을 분리 |
| OCP 개방-폐쇄 | 확장에는 열리고 기존 수정에는 닫힘 | 새 결제 수단을 구현체로 추가 |
| LSP 리스코프 치환 | 하위 타입이 상위 타입의 계약을 지킴 | 호출자가 가정한 동작을 깨뜨리지 않음 |
| ISP 인터페이스 분리 | 사용하지 않는 기능에 의존하지 않음 | 읽기와 쓰기 인터페이스 분리 |
| DIP 의존 역전 | 구체 구현보다 추상에 의존 | 서비스가 저장소 인터페이스에 의존 |

DIP와 의존성 주입은 동일한 용어가 아니다. 의존성 주입은 의존 대상을 외부에서 제공하는 구현 기법이며 DIP를 실현하는 데 사용될 수 있다.

### 3. 디자인 패턴의 상황별 선택

| 패턴 | 분류 | 핵심 상황 |
|---|---|---|
| Singleton | 생성 | 하나의 인스턴스 접근점을 관리 |
| Factory Method | 생성 | 생성할 구체 타입을 하위 클래스가 결정 |
| Abstract Factory | 생성 | 서로 관련된 객체 제품군을 함께 생성 |
| Builder | 생성 | 복잡한 객체의 생성 단계를 분리 |
| Prototype | 생성 | 기존 객체를 복제해 생성 |
| Adapter | 구조 | 맞지 않는 인터페이스를 연결 |
| Decorator | 구조 | 객체를 감싸 기능을 조합 |
| Facade | 구조 | 복잡한 하위 시스템에 단순 진입점 |
| Composite | 구조 | 단일 객체와 트리를 같은 방식으로 취급 |
| Proxy | 구조 | 대리 객체로 접근을 제어 |
| Bridge | 구조 | 추상과 구현을 각각 확장 |
| Flyweight | 구조 | 공유 가능한 상태로 다수 객체의 비용 감소 |
| Strategy | 행위 | 알고리즘을 교체 가능한 객체로 분리 |
| Observer | 행위 | 상태 변경을 구독자에게 알림 |
| State | 행위 | 상태별 동작을 객체로 분리 |
| Command | 행위 | 요청을 객체로 표현 |
| Template Method | 행위 | 처리 순서의 뼈대를 고정하고 일부 단계를 재정의 |
| Iterator | 행위 | 내부 표현을 노출하지 않고 순회 |

**구분 예제**: 외부 결제사의 API 형태를 맞추면 Adapter, 결제 수수료 계산 알고리즘을 바꾸면 Strategy, 결제가 완료됐다는 사실을 여러 서비스에 알리면 Observer다. 비슷한 코드 모양보다 문제에서 요구하는 의도를 찾는다.

### 4. UML과 객체 관계

구조 다이어그램에는 클래스·객체·컴포넌트·배치 등이 있고, 행위 다이어그램에는 유스케이스·활동·상태 등이 있다. 시퀀스 다이어그램은 객체 사이 메시지를 시간 순서로 표현하는 상호작용 다이어그램이다.

| 관계 | 표기와 의미 |
|---|---|
| 일반화 | 실선과 빈 삼각형, 상위 타입을 향함 |
| 실체화 | 점선과 빈 삼각형, 인터페이스 구현 |
| 연관 | 객체 사이의 구조적 연결 |
| 의존 | 점선 화살표, 일시적 사용 관계 |
| 집합 | 전체 쪽의 빈 마름모, 약한 전체-부분 관계 |
| 합성 | 전체 쪽의 채운 마름모, 부분의 생명주기를 전체가 소유 |

집합과 합성의 마름모는 부분이 아니라 전체 쪽에 둔다. 다중성 `0..1`, `1`, `0..*`, `1..*`를 읽을 수 있어야 한다.

### 5. 분석 모델과 4+1 뷰

럼바우의 객체 모델은 구조, 동적 모델은 상태와 사건, 기능 모델은 데이터 흐름과 처리를 다룬다. 4+1 뷰는 논리 뷰, 프로세스 뷰, 개발 뷰, 물리 뷰와 이들을 연결하는 유스케이스/시나리오 뷰다.

### 6. 요구사항, 애자일, 비용

기능 요구사항은 시스템이 수행할 작업, 비기능 요구사항은 성능·보안·가용성·사용성 같은 품질과 제약이다. 리팩토링은 관찰 가능한 외부 동작을 유지하면서 내부 구조를 개선한다.

Scrum의 역할과 이벤트에는 Product Owner, Scrum Master, Developers, Sprint, 계획·일일 점검·리뷰·회고 등이 있다. LOC는 코드 규모, FP는 사용자에게 제공하는 기능 규모를 중심으로 산정한다. COCOMO는 규모와 비용 요인에 기반한 추정 모델이다. UI 설계에서는 직관성·유효성·학습성·유연성을 함께 점검한다.

**실수 점검**: Factory Method와 Abstract Factory, Adapter와 Facade, Strategy와 State의 의도를 각각 설명해 본다.

## 보안/신기술

### 1. CIA와 인증·인가

기밀성은 허가된 주체만 읽게 하는 성질, 무결성은 허가되지 않은 변경을 막고 검출하는 성질, 가용성은 필요할 때 사용할 수 있게 하는 성질이다. 3A는 Authentication(인증), Authorization(인가), Accounting(사용 기록·과금/감사)이다. “누구인가”와 “무엇을 할 수 있는가”를 구분한다.

| 접근통제 | 권한 기준 |
|---|---|
| DAC | 소유자의 재량 |
| MAC | 보안 등급과 강제 정책 |
| RBAC | 역할 |
| ABAC | 주체·자원·환경의 속성과 정책 |

최소 권한은 작업에 필요한 권한만 부여하는 원칙이다. Zero Trust는 위치만으로 신뢰하지 않고 접근 요청마다 정책과 신원을 확인하는 접근이다.

### 2. 웹 공격 비교

| 유형 | 공격이 이용하는 것 | 대응 관점 |
|---|---|---|
| SQL Injection | 입력이 SQL 명령 구조에 섞이는 취약점 | 매개변수화 질의, 권한 제한 |
| XSS | 신뢰하지 않는 내용이 브라우저 코드로 실행 | 문맥에 맞는 출력 인코딩, 적절한 CSP |
| CSRF | 로그인된 사용자의 인증 상태로 원치 않는 요청 수행 | CSRF 토큰, SameSite 등 |
| 경로 조작 | 사용자 입력으로 의도하지 않은 파일 경로 접근 | 경로 정규화와 허용 범위 검증 |

SQL Injection과 XSS는 실행되는 위치가 다르다. CSRF는 사용자가 이미 인증되어 있다는 조건을 이용한다. 단순히 입력 문자열을 몇 개 금지하는 방식만으로 모든 공격을 막는다고 설명하지 않는다.

### 3. 네트워크·시스템·사회공학 공격

DoS는 서비스 자원을 고갈시켜 정상 사용을 방해하고, DDoS는 여러 공격원이 참여한다. DRDoS는 반사 서버를 통해 트래픽이 피해자에게 가도록 유도하며 증폭이 결합될 수 있다. SYN Flooding은 연결 설정 자원, Smurf는 ICMP 반사, DNS 증폭은 큰 응답과 주소 위조의 조합을 이해한다.

스니핑은 트래픽 도청, 스푸핑은 신원·주소 등의 위장이다. 피싱은 위장 메시지·사이트로 정보를 유도하고, 스미싱은 문자 메시지를 이용한다. 파밍은 정상 주소로 접속하려는 사용자를 위조 목적지로 유도한다. APT는 특정 표적에 지속적으로 침투·유지하려는 공격 캠페인을 말한다.

버퍼 오버플로는 버퍼 범위를 넘는 접근, TOCTOU는 검사 시점과 사용 시점 사이 상태 변화의 경쟁 문제다. 제로데이는 알려지지 않았거나 대응 패치가 없는 취약점을 악용하는 상황과 연결된다. 랜섬웨어는 데이터를 암호화하거나 접근을 막아 금전을 요구하고, 웜은 스스로 전파하는 특성이 있다.

### 4. 암호, 해시, 서명

| 구분 | 키와 목적 | 대표 예시 |
|---|---|---|
| 대칭키 | 같은 비밀 키로 암·복호화, 대량 데이터 | AES, 과거의 DES |
| 비대칭키 | 공개 키와 개인 키의 쌍 | RSA, ECC 기반 방식 |
| 해시 | 임의 입력을 고정 길이 값으로 요약 | SHA-256 |
| MAC | 비밀 키로 메시지 인증 값 생성 | HMAC |
| 전자서명 | 개인 키로 서명, 공개 키로 검증 | RSA·ECDSA 서명 |

AES의 블록 크기는 128비트이고 키 길이는 128·192·256비트다. 해시는 원래 평문을 복호화하는 기능이 없다. 전자서명은 문서 전체를 비밀로 만드는 기술과 구별한다. 비밀번호 저장에서는 단순 해시만 반복해서 쓰는 개념을 넘어서 Salt와 비밀번호용 해시 함수의 목적을 이해한다.

대칭키의 빠른 데이터 처리와 비대칭키의 키 교환·서명 역할을 결합하는 방식이 흔하다. 공개키 인증서는 공개키와 주체의 관계를 인증하는 데 사용한다.

## C언어

### 1. 주소, 역참조, 배열

`&x`는 x의 주소이고 `*p`는 p가 가리키는 객체다. `p + 1`은 다음 원소의 위치로 이동한다. 포인터 연산은 자료형 크기에 영향을 받으며 임의의 서로 다른 객체 사이 주소 계산을 그대로 일반화하지 않는다.

```c
int a[] = {3, 6, 9};
int *p = a;
++p;
*p += 1;
printf("%d", a[1]); /* 7 */
```

| 단계 | p가 가리키는 대상 | 배열 |
|---|---|---|
| 초기 | a[0] | 3, 6, 9 |
| ++p | a[1] | 3, 6, 9 |
| *p += 1 | a[1] | 3, 7, 9 |

배열은 많은 표현식에서 첫 원소 포인터로 변환되지만, `sizeof`나 배열 자체에 대한 주소 연산 등에서는 구별해야 한다. `sizeof(a) / sizeof(a[0])`로 배열 원소 수를 계산하는 방식은 배열이 포인터로 전달된 함수 매개변수에 그대로 적용할 수 없다.

### 2. 문자열과 구조체

C 문자열의 끝은 널 문자 `\0`이다. `strlen`은 널 문자 이전의 문자 수이고, 문자 배열의 `sizeof`는 저장 공간 크기다. `char text[] = "ABC";`의 배열 크기는 4이고 문자열 길이는 3이다. 문자열 리터럴을 수정하는 동작은 피한다.

구조체 객체는 `item.count`, 구조체 포인터는 `p->count`로 접근한다. `p->count`는 `(*p).count`와 같다. 이중 포인터 `int **pp`에서 `*pp`는 포인터이고 `**pp`는 정수 객체다.

### 3. 연산자와 출력 추적

전위 증가는 증가 후 값을 사용하고 후위 증가는 이전 값을 사용한 뒤 증가한다. 한 식에서 같은 변수에 대한 여러 변경과 읽기가 순서 보장 없이 섞이는 코드는 결과를 임의로 단정하지 않는다.

정수 나눗셈은 정수 결과이며 `7 / 3`은 2다. `%`는 나머지, `&&`와 `||`는 논리 연산, `&`·`|`·`^`는 비트 연산이다. `^`는 거듭제곱이 아니라 XOR이다. `&&`·`||`의 단축 평가로 뒤쪽 표현식이 실행되지 않을 수 있다.

```c
unsigned int x = 7;
printf("%u", x ^ 3u); /* 111 XOR 011 = 100, 출력 4 */
```

### 4. 재귀와 자료구조

재귀는 종료 조건과 반환 과정을 각각 추적한다. `f(n) = n + f(n-1)`, `f(0)=0`이면 `f(4)=10`이다. Stack은 LIFO, Queue는 FIFO다. 연결 리스트 문제는 head, next, NULL을 표시하고 링크가 바뀌는 순서대로 그린다.

### 5. 함수 전달과 메모리

C는 인자 값을 복사해 전달한다. 호출자 객체를 변경하려면 그 객체의 주소를 전달하고 함수 안에서 역참조한다. 지역 변수의 주소를 반환하여 수명이 끝난 객체를 참조하지 않는다. 동적 할당은 성공 여부와 해제를 확인하고, 해제한 객체를 재사용하지 않는다.

**실수 점검**: 각 반복의 변수 값, 포인터 대상, 널 문자, 정수 나눗셈, 출력 서식을 별도로 점검한다. 코드를 실행하지 않는 추적 문제에서도 정의되지 않은 동작은 하나의 정답으로 가정하지 않는다.

## Java

### 1. 참조 타입과 실제 객체 타입

필드 접근과 static 메서드의 선택은 참조 표현식의 컴파일 시점 타입을 기준으로 한다. 재정의한 인스턴스 메서드는 실제 객체 타입에 따라 동적으로 선택된다.

```java
class Parent {
    int value = 4;
    int get() { return value; }
}
class Child extends Parent {
    int value = 9;
    int get() { return value; }
}
Parent p = new Child();
System.out.print(p.value + "," + p.get()); // 4,9
```

`p.value`와 `p.get()`을 같은 규칙으로 판단하지 않는다. `super`는 부모의 멤버와 생성자에 접근하는 데 사용하고, `this`는 현재 객체를 뜻한다.

### 2. 오버로딩과 오버라이딩

오버로딩은 같은 이름에 서로 다른 매개변수 목록을 정의하는 것이다. 메서드 선택에는 컴파일 시점의 인자 타입이 중요하다. 오버라이딩은 상속받은 인스턴스 메서드를 재정의하는 것이다. 반환 타입만 다른 선언은 오버로딩이 아니다.

| 구분 | 선택 기준 | 단서 |
|---|---|---|
| 오버로딩 | 컴파일 시점의 선언 타입과 시그니처 | 매개변수 목록 차이 |
| 오버라이딩 | 실제 객체의 인스턴스 메서드 | 상속과 재정의 |
| 필드 하이딩 | 참조 표현식의 타입 | 부모와 자식의 같은 이름 필드 |
| static 하이딩 | 컴파일 시점 타입 | static은 인스턴스 동적 바인딩과 다름 |

### 3. 생성자와 static

일반적인 실기 생성자 예제에서는 부모 생성 과정 후 자식 생성 과정이 진행된다. 명시적 부모 생성자 호출이 생략된 경우 기본 `super()` 호출 가능 여부를 확인한다. 생성자는 반환 타입을 갖지 않으며 메서드처럼 상속되지 않는다.

static 필드는 클래스에 속하므로 객체들이 공유한다. 객체마다 따로 저장되는 인스턴스 필드와 구별한다. 정적 초기화, 인스턴스 초기화, 생성자 순서를 문제의 코드에서 추적한다.

### 4. 문자열, 동등성, 컬렉션

참조형의 `==`는 같은 객체를 참조하는지 비교한다. `String.equals()`는 문자열 내용을 비교한다. 문자열 리터럴과 `new String()`을 섞은 문제는 내용이 같은 것과 참조가 같은 것을 분리해서 판단한다.

List는 순서와 중복을 허용하고, Set은 중복을 허용하지 않으며, Map은 키와 값의 대응을 관리한다. 구체 구현에 따라 정렬·반복 순서가 다르므로 모든 Set과 Map의 순서를 단정하지 않는다. 제네릭은 타입 안전성을 높이고 형변환 필요를 줄인다.

### 5. 예외와 추상화

try에서 예외가 발생하면 맞는 catch로 흐름이 이동하고, finally는 정리 작업에 사용한다. 예외 처리 문제는 예외 발생 이후 실행되지 않는 문장을 표시한다. finally의 return이 이전 반환을 덮어쓸 수 있어 반환값과 제어 흐름을 함께 본다.

추상 클래스는 공통 구현과 상태를 둘 수 있고, 인터페이스는 타입의 계약을 표현한다. 함수형 인터페이스는 하나의 추상 메서드를 가지며 람다의 대상이 될 수 있다. `final` 변수, 메서드, 클래스는 각각 재대입 제한, 재정의 제한, 상속 제한이라는 서로 다른 뜻이다.

**실수 점검**: 참조 타입·실제 타입·메서드 시그니처를 표에 나누어 적고, 생성자 호출과 공유 필드 변경을 순서대로 기록한다.

## Python

### 1. 인덱스와 슬라이싱

슬라이싱은 `start:stop:step`이며 stop은 제외한다. 음수 인덱스는 뒤에서 세고, 음수 step은 역방향이다. 생략한 경계는 진행 방향에 맞는 기본값을 사용한다.

```python
values = [10, 20, 30, 40, 50, 60]
print(values[1:6:2])  # [20, 40, 60]
print(values[::-1])   # [60, 50, 40, 30, 20, 10]
```

### 2. 대입, 얕은 복사, 깊은 복사

대입 `b = a`는 리스트를 복제하지 않고 같은 객체를 참조한다. `a[:]`와 `list(a)`는 바깥 리스트를 얕게 복사한다. 내부에 중첩 리스트가 있으면 내부 객체는 공유될 수 있다.

```python
a = [1, 2]
b = a
c = a[:]
b.append(3)
print(len(a), len(c))  # 3 2
```

깊은 복사는 중첩 구조의 객체 복사까지 고려한다. `==`는 값 비교이고 `is`는 객체 정체성 비교다.

### 3. 딕셔너리, 집합, 순서

딕셔너리의 `get(key, default)`는 키가 없을 때 기본값을 반환한다. `d[key]`는 키가 없으면 KeyError가 날 수 있다. 현재 Python의 dict는 삽입 순서를 유지하지만 set은 원소 순서에 의존해서 답을 쓰지 않는다.

```python
items = ["x", "y", "x", "z", "x"]
counts = {}
for item in items:
    counts[item] = counts.get(item, 0) + 1
print(counts["x"])  # 3
```

### 4. 반복과 내포, 제너레이터

`range(1, 5)`의 값은 1,2,3,4다. 리스트 내포는 새 리스트를 만들고, 제너레이터 표현식은 필요할 때 값을 생성한다. 제너레이터는 소비한 값을 일반 리스트처럼 계속 다시 순회할 수 있다고 가정하지 않는다. `yield`는 값을 내보내면서 함수 실행 상태를 유지한다.

```python
print(sum(n * n for n in range(1, 4)))  # 1 + 4 + 9 = 14
```

### 5. 연산과 함수의 함정

`/`는 일반 나눗셈이고 `//`는 바닥 나눗셈이다. `-7 // 3`은 -3, `-7 % 3`은 2다. `**`는 거듭제곱이다. 함수의 기본 인자로 가변 리스트를 사용하면 호출 사이에 같은 리스트가 유지될 수 있다. `None`을 기본값으로 두고 호출마다 리스트를 만드는 방식과 구별한다.

문자열은 불변이고 리스트는 가변이다. 문자열의 `join`은 문자열 원소를 연결한다. 클래스 문제에서는 클래스 변수와 인스턴스 변수를 구별하고 `self`가 가리키는 객체를 확인한다.

**실수 점검**: 출력이 리스트인지 공백으로 구분된 값인지 확인한다. 슬라이싱 stop, 복사 깊이, 가변 기본 인자, 제너레이터 소모 여부를 점검한다.

## SQL

### 1. SELECT의 논리 처리 순서

FROM/JOIN → WHERE → GROUP BY → HAVING → SELECT → DISTINCT → ORDER BY 순서로 이해한다. 이는 결과를 추론하는 논리 순서이며 실제 DBMS의 물리 실행 계획과 항상 같은 것은 아니다.

| 단계 | 결정할 것 |
|---|---|
| FROM/JOIN | 어떤 행을 대상으로 할 것인가 |
| WHERE | 개별 행 중 무엇을 남길 것인가 |
| GROUP BY | 어떤 값으로 행을 묶을 것인가 |
| HAVING | 어떤 그룹을 남길 것인가 |
| SELECT | 어떤 열과 식을 출력할 것인가 |
| ORDER BY | 결과를 어떤 순서로 보여줄 것인가 |

### 2. 집계와 NULL

`COUNT(*)`는 행 수, `COUNT(column)`은 해당 값이 NULL이 아닌 행 수다. SUM과 AVG 등 일반적인 집계는 NULL을 제외한다. NULL 비교는 `= NULL`이 아니라 `IS NULL`을 사용한다. SQL 조건에는 참·거짓뿐 아니라 UNKNOWN이 있으며, WHERE는 참인 행만 남긴다.

**예제**: 점수 80, NULL, 100 세 행이면 `COUNT(*)=3`, `COUNT(점수)=2`, `AVG(점수)=90`이다. NULL을 0으로 대체해서 계산하라는 조건이 없으면 임의로 0을 넣지 않는다.

### 3. GROUP BY와 HAVING

```sql
SELECT department, SUM(amount) AS total
FROM sales
WHERE amount >= 20
GROUP BY department
HAVING SUM(amount) >= 70
ORDER BY department;
```

먼저 20 미만의 개별 행을 제거하고, 부서별로 합을 계산한 뒤 합이 70 이상인 그룹만 출력한다. SELECT의 비집계 열은 일반적으로 GROUP BY에 대응해야 하며 DBMS의 추가 허용 규칙은 별도로 확인한다.

### 4. JOIN과 결과 행 수

INNER JOIN은 일치한 행만, LEFT JOIN은 왼쪽 행을 모두 남기며 매칭이 없는 오른쪽 열은 NULL이다. 하나의 왼쪽 행이 오른쪽 두 행과 일치하면 결과가 두 행으로 늘어난다. 관계가 일대일인지 일대다인지 먼저 확인한다.

**예제**: 학생 1,2,3 중 신청 테이블에 1이 두 번, 3이 한 번 있으면 INNER JOIN은 3행, LEFT JOIN은 매칭이 없는 학생 2를 포함하여 4행이다. LEFT JOIN 후 WHERE에서 오른쪽 열의 조건을 요구하면 매칭이 없는 행이 제거될 수 있다. ON의 조건과 WHERE의 조건 위치를 구별한다.

### 5. 서브쿼리와 집합 연산

IN은 집합 내 포함 여부, EXISTS는 서브쿼리 결과의 존재 여부를 검사한다. 상관 서브쿼리는 바깥 행의 값을 참조한다. NOT IN의 대상에 NULL이 있으면 UNKNOWN 때문에 예상과 다른 결과가 나올 수 있다.

UNION은 중복을 제거하고 UNION ALL은 중복을 유지한다. 집합 연산을 연결하는 SELECT들의 열 수와 자료형 호환성을 확인한다. ORDER BY 없이 결과 순서가 보장된다고 가정하지 않는다.

### 6. DDL, DML, DCL, TCL

| 분류 | 명령 | 주요 목적 |
|---|---|---|
| DDL | CREATE, ALTER, DROP | 구조 정의·변경 |
| DML | INSERT, UPDATE, DELETE | 데이터 변경 |
| DCL | GRANT, REVOKE | 권한 부여·회수 |
| TCL | COMMIT, ROLLBACK, SAVEPOINT | 트랜잭션 제어 |

SELECT를 DML에 포함하는 분류와 DQL로 구분하는 분류가 있으므로 문제의 체계를 따른다. DELETE는 행 삭제, DROP은 객체 제거, TRUNCATE는 테이블 전체 행 제거를 위한 별도 명령이다. TRUNCATE와 DDL의 커밋·롤백 동작은 DBMS에 따라 다르므로 보편적인 단정은 피한다.

### 7. 제약조건과 뷰

PRIMARY KEY는 유일성과 NULL 불가, UNIQUE는 유일성 제약, NOT NULL은 NULL 불가, CHECK는 값의 조건, FOREIGN KEY는 참조 관계를 표현한다. UNIQUE에서 NULL을 다루는 세부 규칙은 DBMS별로 확인한다. View는 질의를 기반으로 한 논리적인 테이블 표현이며 모든 뷰가 자유롭게 수정 가능한 것은 아니다.

### 8. 윈도 함수와 순위

`ROW_NUMBER()`는 행마다 번호, `RANK()`는 동점 다음 순위를 건너뛰는 순위, `DENSE_RANK()`는 동점 다음 순위를 건너뛰지 않는 순위다. 윈도 함수의 PARTITION BY는 집계 단위를 나누되 GROUP BY처럼 결과 행을 하나로 합치지 않는다.

**실수 점검**: 결과 행 수, NULL, 그룹의 개수, WHERE/HAVING의 시점, 정렬 기준을 차례로 점검한다. 평균 결과의 자료형이나 소수 표현은 문제에서 지정한 DBMS·출력 조건을 따른다.
